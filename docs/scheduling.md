# Costco Genie: Scheduling

There is one per-user LaunchAgent, `com.costco-genie.daily`. `./costco install-agent` regenerates and loads its plist; `uninstall-agent` removes it and keeps local data. Reinstall after moving the checkout, changing Node, or changing either schedule. Absolute Node and compiled CLI paths, private logs, and working directory are recorded; credentials are not.

The plist is `~/Library/LaunchAgents/com.costco-genie.daily.plist`; output goes to `~/.costco-genie/logs/stdout.log` and `stderr.log`. Installation also boots out the legacy `com.costco-price-matcher.daily` service and deletes its plist before loading the new service. Cleanup errors stop installation; uninstall attempts to remove both labels even if one removal fails. Status/doctor warn about a remaining legacy plist or loaded service. A final scheduled invocation from the old agent can migrate the data and proceed, provided its recorded checkout and Node paths still exist; reinstall after moving the checkout.

`renderLaunchAgent` in `src/scheduler/launchd.ts` renders a `StartCalendarInterval` array: daily watch time (08:00 by default), plus the existing receipt time (09:00 by default) and optional weekday. Receipt weekday uses 0 Sunday through 6 Saturday; null is daily. `RunAtLoad` stays enabled for daily watch catch-up even with weekly receipts. All triggers invoke `node dist/cli.js run --scheduled`.

`dispatchScheduledChecks` calls watch and receipt callbacks sequentially; each takes the matcher's `run.lock` and releases it before the next. No two callbacks open the profile concurrently. A watch failure is reported while receipts still run. Receipt authentication, import, pricing, or delivery failure cannot prevent the earlier watch attempt. A successful receipt result cannot hide a watch failure in the CLI exit code. Manual `run` retains receipt behavior; manual `watch check` checks watches only.

The watch callback skips an empty watchlist and never sends mail for it. `check` skips sources/mail after a successful full watch check on the same local date. A full manual check can satisfy freshness; baseline, filtered, and dry runs cannot. A nonempty check with at least one usable observation and successful required delivery counts as successful. All-unavailable checks fail and preserve prior lows.

`receiptScheduleDue` finds the most recent configured local receipt trigger, including a missed trigger. With no run history, receipts wait until their configured day/time; the initial scheduled skip establishes history for later sleep catch-up. Receipts skip when a successful receipt run or a completed scheduled attempt already covers the trigger. Freshness skips and failed scheduled attempts consume their trigger, so daily watch triggers cannot reschedule a skipped or failed weekly import. Manual failures do not consume receipt triggers. `runPriceCheckLocked` also keeps the existing `scheduledIntervalDays` freshness guard based only on successful runs. Future successful timestamps retain the existing recovery behavior. Weekly receipt semantics remain independent of daily watches.

Launchd coalesces sleep-missed calendar triggers on wake; RunAtLoad catches up on user-agent load/login or installation. Both enter the same independent due/freshness checks. This requires the Mac to be running in the user's session with network access; it does not wake a powered-off Mac. `status` and `doctor` show schedules, active watches, last successful full watch check, the last scheduled failure per job and its notification delivery status, queued alerts, and offline readiness. Profile presence cannot verify authentication.

## Failure emails

Only scheduled dispatch sends failure emails. Receipt `failure` outcomes and sign-in-required outcomes alert, as do receipt/order import failures even if the other import succeeds. Scheduled import failures now have outcome `failure`; interactive import behavior is preserved. A completed receipt check with unresolved prices or a partial price-source result does not alert. Watch status `failure` alerts, including all sources unavailable or failed price-drop delivery. An exception escaping either callback (including lock/storage/report errors) alerts without stopping the other job. Not-due, freshness, and empty-watchlist skips never alert. Interactive `./costco run` and `./costco watch check` print their errors and send no failure email; normal savings/drop emails still apply.

The first failure of each job on each local calendar day reserves one email attempt. This replaces the watch three-consecutive-failures rule and consolidates the old session-expiry email into the failure email. An explicit watch sign-out still updates local session state, but does not send another notice. A usable public watch result can succeed despite a member-price login gate. There is no recovery email.

Completed failures consume the receipt trigger as before. With Friday 16:00 receipts, a failed Friday run otherwise waits until the following Friday at 16:00, even though watches run daily at 08:00. The email gives the next configured local calendar attempt; load/wake may retry failed watches earlier and sleep may delay either job. If a lock/storage/cleanup exception prevents recording a completed receipt attempt, later dispatches may retry sooner. To recover sooner, follow the email's login or doctor guidance.
